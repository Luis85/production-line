# Werk runtime documentation

Start with [archive to main checkout](tutorials/worker-home-to-main.md): extract a
standalone worker into its own home, create a webview request, follow its Git and
request activity, review the increment and explicitly allow its main-checkout merge.
Projects remain visible in WerkHome; runtime and private state stay central.
For retained 0.16 state, use [explicit adoption](how-to/project-worker.md#existing-standalone-installations), then
[connect the shared Markdown queue](how-to/shared-feature-intake.md). Teammates
create ready requests and answer Tasks through committed and pushed files; the
webview is optional. For other deployments, see
[portable Node apps and automation](reference/portable-apps.md).

The release documentation follows [Diátaxis](https://diataxis.fr/): tutorials teach
one complete flow, how-to guides solve operating tasks, reference describes exact
contracts, and explanations describe the system and its limits.

A running Factory or orchestrator also serves `/guide`: a standalone public guide
with no API calls or administrative actions. It explains the model; authenticated
service webviews show current runtime state.

This is the installed-runtime documentation. Source development, original concept
material, implementation backlog and dated review evidence belong to the source
checkout and are not prerequisites for running this release.
