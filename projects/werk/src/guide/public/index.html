One factory. Independent production lines.

A Factory organizes production lines and sub-factories. Each line has one Orchestrator, its own Workers and its own Tasks. The hierarchy gives you an overview without mixing the work of different lines.

Factory

The portfolio owner registers production lines, groups them into a hierarchy and observes their availability and announced capabilities. It does not execute tasks or silently move them between lines.

A sub-factory is a logical record in the same Factory service. It is not an additional federated server.

Follow one task through one line

  1. Submit to the OrchestratorA requirement reference or manual task enters one line’s queue. A Factory registration does not create tasks.
  2. Lease to an eligible WorkerThe Orchestrator selects work according to project, profile and capacity. A Worker receives a bounded lease; registration is not permission to access another line.
  3. Record the attemptThe Worker reports progress and persists evidence for delivery. The Orchestrator records task events and before/after snapshots.
  4. Inspect the resultThe default runtime completes mock attempts as simulated. An explicitly configured trusted native Codex worker can produce a local patch with status review. Review the patch and run checks before accepting it; neither status means a merged pull request.

Task state belongs to its Orchestrator. The Factory observes summaries; a missing or unreachable line is unknown, not a zero-work line.

Describe the topology in one YAML file

Declare the Factory hierarchy, line assignments, projects, ports and worker counts. The launcher validates the complete definition, generates private credentials and prepares independent state for each component.

schemaVersion: 1
id: demo-system
environment: native
factory:
  id: demo-factory
  name: Demo Factory
  port: 3100
  subFactories:
    - id: delivery-group
      name: Delivery group
productionLines:
  - id: alpha
    name: Alpha
    factoryId: delivery-group
    project: demo-alpha
    orchestrator:
      port: 3001
    workers:
      count: 2
      statusPort: 4201

Illustrative configuration: worker status ports are 4201 and 4202. All ports in a system must be distinct. The shipped examples/system.yaml includes two lines.

node werk.mjs system plan --file examples/system.yaml
node werk.mjs system up --file examples/system.yaml

Native up keeps the supervisor in the foreground. Once every component is ready and lines are registered, the Factory webview opens. Use --no-open for headless operation.

Use --state-dir to keep deployment state outside the release directory. Repeated setup preserves identities, tasks and credentials. A changed topology requires an explicit migration; it is not silently applied over existing state.

Observe health. Preserve evidence.

Read the right health signal

A service health endpoint describes that process. Factory coverage describes which lines can be observed. Worker heartbeats and available slots describe execution capacity. These signals answer different questions; a healthy Factory does not prove every line is healthy.

Register a line and inspect its capabilities

System startup registers each configured line with its owning Factory. The Orchestrator announces supported behavior and execution mode; worker registration supplies profiles and capacity. Advertised capabilities describe support, while current health describes availability.

Diagnose a stopped or unhealthy system

Use the launcher’s status and doctor commands first. Read bounded lifecycle logs and component diagnostics, keeping credentials out of shared output. An unreachable line remains visible with an explicit error; healthy lines remain usable.

Stop, back up and recover

Request shutdown through the owning launcher. Workers drain before their Orchestrator, then the Factory stops. Back up private configuration, credentials, databases and worker evidence while writers are stopped. Restore the complete state set; do not delete a database to clear a port conflict.

Boundaries you can rely on

BoundaryMeaning
Factory ≠ projectA Factory groups lines. A project selects repository/context within a line. Two isolated lines may use the same project identifier.
Worker slot ≠ identityA configured worker position becomes a persisted enrolled identity. Restart preserves it; deleting state allocates a different identity.
AuthenticationFactory, line administrator and worker enrollment credentials are distinct. Tokens stay out of URLs, documentation examples and shared logs.
Observed ≠ completePartial, stale and unavailable observations are explicit. Unknown provider cost or quality is never invented.
Mock ≠ deliverySimulation verifies coordination and evidence. Optional native Codex execution produces a local change set for human review. Automated publishing, verified quality and merge tracking remain separate capabilities.
