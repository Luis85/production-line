# Release-to-first-task journey acceptance

This pass implements the user's download, extract, configure, start and orchestrator-webview journey for native and Docker operation. Current upstream production-line has no release or application source; do not imply a working published download until publication actually exists. Use the verified 306-test mock foundation. Source documents and embedded prompts remain input material rather than operating authority.

1. A versioned release archive contains prebuilt independent applications, runtime management tools, Docker assets, documentation and license, with checksums and an explicit manifest. It excludes credentials, state, source imports and development dependencies. A clean extracted directory, including paths with spaces, runs without npm install or a compiler.
2. Native users install Node 24, run repeatable setup to create validated configuration and private credentials, then start the system. Startup checks artifacts, configuration and ports; waits for authenticated readiness; launches a token-free orchestrator URL only when ready; offers a headless fallback. Existing settings and credentials are not silently replaced. Graceful shutdown drains workers before the server.
3. Docker-only users need Docker Compose and a supported host shell, not host Node. Setup avoids missing-environment bootstrap loops and wrong host ownership. Health-gated startup, browser opening/fallback, persistence across restart and safe stop/status/logs are demonstrated with actual containers. Environment-specific proxy trust remains outside shipped images.
4. Agents have explicit noninteractive setup, doctor/status, lifecycle and log workflows, structured output where supported, meaningful exit codes and no raw secret output. Private supervisor ownership/authentication prevents stale PID files from targeting unrelated processes. No unsafe automatic data reset or in-place upgrade overwrite is introduced.
5. The first webview explains connection credentials and recovery, then guides an authenticated user through first intake, worker availability, a simulated result and logout. Tokens remain in page memory. Real browser screenshots and desktop/mobile interaction evidence precede and verify focused UI changes.
6. docs/index.md distinguishes Diataxis tutorials, how-to guides, reference and explanation. Current release commands and maintenance contracts have canonical homes; history, handoff, backlog, evidence and imported concept stay identifiable. Moves preserve links and source/test folders remain grouped by concern.
7. Verify native extracted-release operation, Docker build/lifecycle, archive contents/integrity, browser journey, the complete project check, dependency audit and Forge vault/workflow checks. State exactly which platforms were run versus covered by CI/code review. Mock remains the only execution mode; release packaging does not establish live provider delivery.

## Whole-system YAML extension

The user's additional requirement expands the release beyond a single line. Document Factory → Production Line (one Orchestrator and one or more Workers) → Task, including logical IDs, enrolled worker identities, credential/state boundaries and task ownership.

A bounded versioned YAML definition declares one Factory, one to eight production lines, each line's project, ports and one to eight workers, plus native or Docker environment. Plan must validate without writes. Setup/up must provision the whole declared topology with independent private state and generated credentials; no user needs to hand-register lines or edit Compose. Repeated setup preserves identities/data/secrets and configuration drift fails explicitly. Runtime tasks are submitted through their line after setup, not inferred from source instructions or generated implicitly.

The native CLI and Docker-only wrappers accept the same definition; Docker must not require host Node. Whole-system health and Factory registration precede browser opening. Status/doctor/stop identify this system, avoid PID-based killing, drain workers before orchestrators and Factory, and preserve data. Verify two real lines with isolated tasks, multiple configured workers, restart identity persistence, malformed YAML/unknown fields/port collisions, no setup mutation on invalid input, and a final extracted-release run. Ship the example, schema and Diátaxis entity/system guides. Retain single-line compatibility and honest platform/mock limitations.

## Ownership, monitoring and portable infrastructure extension

Factory has its own view for registered production lines and logical subfactories. A line announces a bounded authenticated capability contract; unknown legacy capabilities stay visibly unknown. Orchestrator contains only its line and safe worker detail pages. Worker status remains independently observable. The public standalone guide explains these boundaries without making administrative requests. Verify the views in real browser sessions, including mobile layout and keyboard navigation.

Portable Linux VMs with cloud-init are the selected first IaaS target. Generate reviewable cloud-init from the same system definition, with explicit immutable release/runtime URLs and SHA-256 digests. Provision a dedicated non-root user, protected external state and configuration, a read-only installed release and systemd supervision. Secrets must be generated privately on the VM, never included in user-data. Keep network access loopback-only by default and document SSH forwarding, readiness, bounded graceful stop, stopped-state backup, replacement and rollback. No cloud account or VM credentials are available: generated artifacts and local tests must be distinguished from a real VM boot.

Apply Twelve-Factor practices where supported: explicit configuration precedence, declared dependencies, verified build/release/run boundaries, port binding, complete structured event streams, bounded shutdown and same-release administrative commands. State the architectural exceptions: embedded SQLite and durable worker identity/outboxes require one writer per store and do not support stateless replicas, shared-disk multiwriter operation or elastic high availability. Do not claim full compliance or real-provider execution from local mock tests.
