# Werk pass 4 review

This pass closes pinned iteration import and durable Factory retry gaps, fixes worker replay/filesystem/diagnostic defects, and improves mobile navigation and uncertain-action recovery. Source and tests retain concern-based organization. Execution remains mock-only. See [acceptance](pass4-acceptance.md) and the [Forge findings report](pass4-cli-report.md), saved before upstream implementation dispatch.

## Product changes

- Explicit `iteration import --context pinned --vault-root docs` uses an authenticated endpoint that independently compares committed feature identity, exact source hash, readiness, iteration, title, criteria and scheduling metadata against the operator-owned binding. Original request replay survives restart, changed binding and unavailable source. Unbound historical tasks cannot masquerade as pinned tasks. Feature and inventory count/byte limits, strict pagination and safe committed Git reads bound collection. Whole iterations are not atomic: completed tasks survive a later submission failure. Branch and PR metadata remain unverified. See [pinned iteration import](../how-to/pinned-iteration-import.md).
- All six Factory mutations accept durable keys through HTTP/CLI; enabled MCP writes require them and the browser retains them for uncertain retries. Schema 2 atomically stores mutation and receipt. Original results survive response loss, restart, concurrent requests, subsequent edits/deletion and credential configuration changes; changed operation/target/normalized payload conflicts. Current authentication remains required. Receipts contain digests and public response metadata, have no automatic expiry, and belong in backups. See [Factory idempotency](../reference/factory-idempotency.md).
- Worker terminal replay validates task, worker, project, attempt, profile and immutable source/context provenance before completion or publication. Orphan or mismatched evidence fails closed. Journal operations reject a replaced state-root symlink. Remote HTTP error text no longer enters worker diagnostics; safe status/retry classification remains available.
- Mobile task/worker identity columns stay readable inside scrolling tables. Lower pagination controls avoid a long return scroll. Successful explicit navigation focuses the new summary; polling, errors and superseded requests preserve focus. Factory creates, updates and deletes retain their key and intent after an uncertain response; changed actions rotate it. Tokens and retry keys remain in page memory, so reload does not promise continuity.

## Structure and review

Factory intent normalization belongs in application/mutations, while SQLite receipts and migrations live in infrastructure/idempotency and infrastructure/schema. Worker evidence identity is a pure application concern; journal checks remain in infrastructure/journal. Import policy and Git/HTTP adapters retain their intake boundary. New tests live in factory, orchestrator/context, worker, shared/mcp and ui/runtime. CLI/composition roots and distribution paths remain stable; no extra cosmetic moves were needed.

Independent review examined Factory atomicity, replay ordering, normalization, credential privacy and MCP; the orchestrator and worker owners reviewed provenance compatibility. Parent review identified inconsistent inventory metadata and legacy cached-task replay, both fixed with regression tests. Source/doc review also corrected outdated claims in architecture, developer, API, MCP and handoff guidance while retaining historical pass reports.
