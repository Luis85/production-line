# Werk pass 3 acceptance

This pass connects the existing immutable context resolver to opt-in server-owned project binding and worker evidence, and migrates product consumers to bounded pagination. Mock execution remains the default and sole adapter; source documents never authorize provider or Git side effects.

1. Operator configuration owns local repository, exact commit and vault root. Minimal requirement intake resolves a ready committed note before task creation; invalid or cross-project requests fail without queued work. Persist an immutable manifest separately from task lists, preserve retry/idempotency across restart and binding changes, bound concurrent resolution and shutdown, and migrate old mock databases without rewriting evidence.
2. An assigned worker obtains and verifies the stored manifest before its mock adapter runs. Snapshots bind its digest without copying source text into telemetry. Wrong workers, missing/mismatched context and lease loss fail closed; old unbound mock tasks and durable result replay continue working.
3. Task, worker and event UI journeys fetch bounded pages with explicit continuation, current-page filtering/counts, retry and stable selected-task behavior. Preserve authentication recovery and show incomplete inventories honestly. Verify in desktop/mobile Chromium.
4. MCP list tools default to bounded pages and expose validated continuation inputs. Address reproduced transport resource defects with meaningful HTTP/stdio tests while preserving redaction and read-only defaults.
5. Run independent review, TypeScript, native builds and all tests, dependency audit, and Forge document/backlog/workflow gates. Record concrete tools used, friction, needed capabilities and verification limits.
6. Group source and tests by concern, preserving public CLI/build contracts, updating imports and recursive test discovery, and proving all original test files remain included. Review the Forge changes against its established concern folders.
7. Save the CLI audit before dispatching dedicated upstream implementation agents. Use an independent main-based Forge branch, reviewed changes, portable tests and generated-output checks, then open a new pull request without merging it.

This is a coherent product improvement pass. Remaining live provider, publication, review/merge, deployment and full Obsidian support gaps remain visible rather than being marked complete by fixture success.
