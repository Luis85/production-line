# Worker intake to published release

Deliver the default standalone workflow from a registered project's Feature Request through provider execution, independent verification and a Git/Markdown PullRequest handoff followed by review and explicit permission for the worker's guarded merge into the displayed assigned main checkout. GitHub hosting-service PRs, managed merge, exact-source build and GitHub Releases are an explicitly committed and locally approved optional extension. A GitHub URL or installed `gh` is not integration consent.

The selected optional live pilot is native Windows with Claude Code CLI and GitHub Release assets. Git-only real-Git fixtures separately qualify the default handoff and opt-in boundary. Keep this feature Active until its [acceptance ledger](../../reports/worker-release-workflow-acceptance.md) has actual live evidence. Automated source/fixture checks and native/live qualification are separate requirements.

See the [workflow contract](../../reference/worker-release-workflow.md) and [operating guide](../../how-to/deliver-worker-release.md). Existing imported P0 items retain their distinct leased line/orchestrator scope; reuse does not blanket-complete them.
