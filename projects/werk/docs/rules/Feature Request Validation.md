# Feature Request validation

The same canonical request validators apply to webview, CLI and Markdown intake. The worker validates the selected registered project, stable ID, supported document version, bounded title/body, acceptance criteria, template identity, priority and approved relative file paths. HTML is displayed inertly; submitted text cannot grant tools or set trusted execution facts.

Template preparation creates a draft. Readiness and submission are separate decisions. Invalid fields return actionable findings and preserve user text. Reusing one operation ID with another payload is rejected; replaying an identical accepted command returns its retained receipt.

Shared-Git intake confirms the committed remote request and its durable claim before execution. Duplicate IDs, ambiguous sources, missing baselines, out-of-root references and conflicting edits block new work until reconciled. Generated worker status cannot manufacture acceptance or check evidence.

See [request gates](../reference/request-gates.md), [feature-request format](../reference/feature-requests.md) and [Definition of Ready](../../quality/Definition%20of%20Ready.md).
